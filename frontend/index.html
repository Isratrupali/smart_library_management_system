⚙️ Architecture

6 Design Patterns

Every core operation is powered by a Gang-of-Four design pattern.

🔒
Singleton

One shared SQLite connection for the entire app — prevents duplicate connections.

Database::getInstance()
🏭
Factory

Creates Student, Librarian, or Admin user objects with different permissions and limits.

UserFactory::create(role)
⚡
Strategy

Swap book sort algorithms at runtime: by title, author, year, or popularity.

BookSorter::setStrategy(sort)
🎨
Decorator

Layer search filters independently: keyword + genre + availability + type.

SearchFilterBuilder().build()
👁️
Observer

Auto-notifies waitlisted users the moment a returned book becomes available.

WaitlistNotifier::notifyWaitlist()
📋
Command

Encapsulates borrow and return as command objects with full validation and undo support.

BorrowCommand::execute()

👥 User Roles

Three Role Dashboards

🎓
Student
  • Browse and search book catalog
  • Borrow & return books
  • Read ebooks / listen audio
  • Upgrade membership tier
  • Book reading room seats
  • View notifications & fines
📋
Librarian
  • Add / edit / delete books
  • Manage book copies
  • Monitor all active borrows
  • Process student returns
  • View overdue reports
  • Send notifications to users
⚙️
Admin
  • Manage all users & roles
  • Control membership plans
  • View system statistics
  • Approve book requests
  • Suspend/activate accounts
  • Full system settings
